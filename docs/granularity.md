# “挨着但没去过”：颗粒度怎么划分

更新：2026-11-26 · 状态：第 4 节是当前方案（用维基百科基础条目代替 Google 的类别表），第 2、3 节的方案已否决

## 0. Google 那张表开源了吗？

**没有。** 那 761 个类别是从他们自己平台上的全部视频聚类出来的（视频的标题、标签、画面、声音 → 向量 → 分层聚类，每个类别大小差不多）。论文里没有公开这张表。就算公开了，它分的也是“视频内容”，不是“点子”，直接拿来也用不上。

Google 公开过另一张兴趣分类表：Chrome 的 Topics API 用的那张，469 个话题、22 个大类（[来源](https://developer.chrome.com/blog/topics-enhancements)）。广告行业也有一张公开的：IAB 内容分类表，大约 700 个类别、4 层，按 CC BY 3.0 协议发布（[GitHub](https://github.com/InteractiveAdvertisingBureau/Taxonomies)）。这两张表都分得比较成熟，但也都只分“兴趣”。

## 1. 好的颗粒度要满足什么

| # | 要求 | 为什么 |
| --- | --- | --- |
| 1 | **同一层** | 所有方向的大小差不多，“新”才有意义。不然“科技”和“盆景”放在一起没法比 |
| 2 | **大小均匀** | Google 特意把类别做成一样大。不然大类会把所有点子都吸进去 |
| 3 | **有远近** | 要能分出“挨着”和“很远”，最好不靠模型临时判断 |
| 4 | **盖得住问题** | 周末项目、副业、学东西、送礼、读书……都要能用 |
| 5 | **记忆和点子能放在同一张表上** | 才能判断某个点子落在“亮的”还是“暗的”位置 |
| 6 | **稳定** | 同一个人问两次，表是同一张，结果才能复现、才能测 |

## 2. 四种做法比较

| 做法 | 1 同层 | 2 均匀 | 3 远近 | 4 覆盖 | 5 同表 | 6 稳定 | 成本 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A. 每次让模型临时列一张方向表 | ✗ | ✗ | 半 | ✓ | ✓ | ✗ | 低 |
| B. 直接用现成的兴趣分类表（IAB / Chrome Topics） | ✓ | ✗ | ✓（树） | 半 | ✓ | ✓ | 低 |
| C. 照搬 Google：自己造一大堆点子，再聚类建表 | ✓ | ✓ | ✓（树） | ✓ | ✓ | ✓ | 中（一次性） |
| D. 把点子拆成几个维度（下面详细讲） | ✓ | 半 | ✓（数换了几个维度） | ✓ | ✓ | ✓ | 低 |

- **A 的问题**：模型这次列得粗（“手工”），下次列得细（“木工榫卯”），颗粒度每次都不一样，没法测。
- **B 的问题**：表里只有“兴趣领域”，而一个点子不只是一个领域。“给学生修电动车”的领域是修车，但真正让它变新的，是“对象换成了学生”。另外表的大小不均匀，有的大类特别大。
- **C 的问题**：要先造点子池。点子池如果全由同一个模型生成，本身就是千篇一律的（benchmark 已经看到：不带记忆时，每个人都收到“用 Python 写脚本”）。造的时候要用很多不同的人设去生成，用来当人设的现成数据集有许可证限制（PersonaHub 公开的 20 万人设是非商用、相同方式共享）。

## 3. ~~推荐：D（拆维度）~~ 已否决：没有泛化能力

维护者 2026-11-26：自定的词表（7 种做法、7 种对象）换一类问题就用不上，等于又回到了“手画地图”。另一个方案“每个问题现场造 60 个点子再分堆”也否决了，原因是太重、太慢，而且模型造出来的答案池本身就雷同，可能的点子太多也没法遍历。

下面保留原文作记录。

### 原方案

### 3.1 一个点子 = 三个维度

| 维度 | 意思 | 词表从哪来 |
| --- | --- | --- |
| **领域**：做什么 | 面食、修车、园艺、编程…… | IAB 内容分类表的第 2 层（约 320 个），只需翻译一次 |
| **做法**：怎么做 | 做、学、卖、教、帮、记录、组织 | 固定 7 个，我们自己定 |
| **对象**：给谁 | 自己、家人、朋友、学生、邻居、同行、陌生网友 | 固定 7 个，我们自己定 |

**颗粒度就由这三张词表定死。** 领域用现成表的第 2 层，大约是“一个人能说出‘我懂这个’”的大小。做法和对象各 7 个，是够用的最少数量。

### 3.2 “亮”“挨着”“远”就有了清楚的定义

- 每条记忆点亮它涉及的维度值。比如“会修电动车”点亮领域 = 修车；“店在大学城旁边”点亮对象 = 学生。
- 一个点子的三个维度：
  - **三个全亮 = 打圈**：在已有的东西里打转；
  - **换掉一个 = 挨着**：借得上他已有的东西，但确实是新的；
  - **换掉两个或三个 = 远**。

### 3.3 拿老马试一下

亮着的：领域 = 面食、修车、钓鱼（已过时）；做法 = 做、卖；对象 = 自己、学生、同行。

| 点子 | 领域 | 做法 | 对象 | 判定 |
| --- | --- | --- | --- | --- |
| 改良臊子配方 | 面食 ● | 做 ● | 自己 ● | 打圈 |
| 跟学生社团办扯面体验课 | 面食 ● | **教** ○ | 学生 ● | 挨着 |
| 收旧电动车修好卖给学生 | 修车 ● | 卖 ● | 学生 ● | 打圈（组合新，但三个维度全亮） |
| 把老家的菜录成口述菜谱 | 面食 ● | **记录** ○ | **家人** ○ | 远 |
| 阳台种葱蒜香菜 | **园艺** ○ | 做 ● | 自己 ● | 挨着 |

（● 亮，○ 没亮。点子是示意，不是运行结果。）

可以看到一个现象：“收旧电动车卖给学生”三个维度全亮，按定义算打圈，但人看起来会觉得挺新。这就是这个定义的边界：**它测的是“用到的东西是不是新的”，不测“组合是不是新的”**。我觉得第一版可以先接受，benchmark 里会单独统计这一类。

### 3.4 插件里怎么用

1. **离线，做一次**：把领域词表翻译成中文，算好向量。
2. **记忆贴标签**：每条记忆点亮哪些维度值，存缓存。用向量找候选，再让模型确认。
3. **第四路**：随机抽 2 条记忆当起点，各换掉一个维度 → 挨着的方向；随机挑几个全暗的组合 → 远的方向。**挑哪个维度值由代码按词表来选，不由模型自由发挥**，所以颗粒度是稳定的。模型只负责把选出来的组合写成一句话的方向。
4. **检查**：用向量算相似度，跟记忆太像的方向丢掉，作为兜底。

### 3.5 怎么验证这个划分好不好

在 benchmark 里给每个点子也贴上三维标签，再看：

- 不带记忆、带记忆、加了插件这几组，“打圈 / 挨着 / 远”的比例各是多少；
- 点子落在多少个不同的领域里（覆盖面）；
- 抽 50 个，让维护者人工判断“三维判定”和自己的直觉一不一致。

如果“领域”那一维的大小严重不均（比如“科技”吞掉一大半），第二版再按做法 C，用点子池重新聚类，替换掉领域词表。


## 4. 当前方案：用维基百科“基础条目”代替 Google 的类别表

### 4.1 为什么是它

英文维基百科有一份人工挑选的“基础条目”（Vital articles），分 5 级，每一级包含上一级的全部条目（[来源](https://en.wikipedia.org/wiki/Wikipedia:Vital_articles)）：

| 级别 | 条目数 |
| --- | --- |
| 1 | 10 |
| 2 | 100 |
| 3 | 1,000 |
| 4 | 10,000 |
| 5 | 50,000 |

它刚好满足第 1 节的要求：

- **同一层、大小大致均匀**：每一级都是按“重要程度相当”人工挑出来的。第 3 级的 1000 个，和 Google 规划用的那一层（761 个）是同一个量级。
- **有远近**：条目本身按大类分组，比如人物、历史、地理、艺术、日常生活、技术、科学；另外每个条目都能算向量，向量之间的距离就是远近。
- **通用**：覆盖全部人类知识，不针对某一类问题，也不需要我们自己定词表。
- **现成、稳定**：不用造答案池，也不用遍历。

### 4.2 和 Google 一一对应

| Google | Widen |
| --- | --- |
| 761 个兴趣类别，每个带文字描述 | 第 3 级的 1000 个基础条目，每个用标题和第一句话当描述 |
| 用户看过的视频 → 属于哪个类别 | 用户的每条记忆 → 离它最近的条目（向量） |
| 随机抽 2 个亮的类别 | 随机抽 2 个亮的条目 |
| 大模型预测一个新类别，**只能从表里选** | 大模型从候选条目里选，**只能从表里选**。候选包括：亮条目附近但没亮的（近），加上随机抽的几个（远） |
| 在新类别里，由原来的推荐模型挑视频 | 在选中的条目上，由模型针对这个问题出点子，再用记忆检查合不合适 |

### 4.3 老马走一遍（示意）

1. **离线，做一次**：下载第 3 级条目，算出每个条目的向量。
2. **点亮**：老马的记忆分别落到最近的条目上，比如 Cooking（烹饪）、Motorcycle（摩托车）、Fishing（钓鱼）、Chinese opera（戏曲）、Xiangqi（象棋）。
3. **随机抽 2 个**：假设抽到 Cooking 和 Motorcycle。
4. **候选**：它们附近、但没亮的条目，比如 Fermentation（发酵）、Bicycle（自行车）、Battery（电池）；再随机加几个远的，比如 Oral history（口述历史）、Gardening（园艺）。
5. **选**：模型只能从候选里选，比如选了 Fermentation 和 Oral history。
6. **出点子**，然后用记忆检查：
   - 发酵 → 试做几种面食的老面、酵头，周一下午做；
   - 口述历史 → 给老顾客录“一碗面的故事”。

### 4.4 还要定的

- **用第 3 级还是第 4 级**：第 3 级 1000 个，颗粒度和 Google 接近；第 4 级 1 万个，分得更细。先做第 3 级，再用 benchmark 比较两者。
- **条目是“知识主题”，不是“做法”**：从“发酵”到“试做老面”，这一步要靠模型自己搭桥。搭桥的质量由“合适率”来把关。
- **语言**：表用英文版。Mem0 存的记忆本来就是英文，正好对得上。显示给用户时，中文名可以从维基数据（Wikidata）里取。
- **准备工作**：下载条目列表（几 MB），在本地给 1000 个条目算一遍向量（几分钟）。
- **TODO（后续颗粒度优化）**：
  - [ ] **离线清洗维基第 3 级条目**：过滤掉具体人物、国家、历史事件、天体等纯百科名词，只保留“学科/技术/艺术/生活/社会活动”等能转化为行动方向的条目（预计剩 300～500 个），避免“远路”随机抽到无法落地的词条。
  - [ ] **探索更贴近“人的行动”的外部表**：v1 跑通后，对比“维基百科第 3 级（清洗后）”与“可行动领域表”（如 O*NET/ESCO 技能树中层、GitHub Topics / 社区兴趣分类等），解决纯百科名词和生活创意问题之间的语义鸿沟。
  - [ ] **两段式颗粒度（粗表锁死 + 现场细化）**：粗颗粒度继续由固定表控制以保证稳定和可测，选中条目后再结合当前问题现场细化一跳（例如从“发酵”细化到具体场景），兼顾覆盖面和接地气。

## 5. 第 3 级实测结果和修正（2026-11-26）

### 5.1 用向量把记忆对到条目上：失败

拿小林和老马在 Mem0 里的记忆，用本地向量模型（nomic-embed-text）找最近的条目，结果大量对错：

- “开了十年面馆，会扯面” → 马铃薯
- “爱听秦腔” → 秦始皇
- “做了三年 Go 后端” → 理智
- 很多记忆都扎堆落到“记忆”“理智”这类很空泛的条目上

原因：Mem0 的记忆是英文夹中文的句子，比如 “saozi (臊子)”；向量模型主要懂英文；条目的说明又只有几个词的短简介。

### 5.2 第 3 级太粗，也太偏

- 1000 个条目里，人物、地理、历史大约占 3 成，基本当不了点子的方向。
- 缺很多日常的东西：编程、软件、象棋、园艺、跑步、摩托车、发酵都不在里面。

### 5.3 修正后的做法

| 步骤 | 做法 |
| --- | --- |
| 表 | 第 4 级（约 1 万个），去掉人物、地理、历史 |
| 记忆 → 条目 | **由大模型选**：先选小类，再在小类里选条目。每条记忆只选一次，结果缓存 |
| 条目 → 近 / 挨着 / 远 | **用向量算，不调模型**：先算余弦相似度，再做去中心（让相似度拉开），再用 CSLS 修正（给到处都像的“万金油”条目扣分），最后**按排名分档**，不看分数绝对值 |
| 远 | 不取最不像的（实测全是行星、化学元素），在中间偏远的位置随机抽 |

第 3 级上的实测（去掉人物、地理、历史后剩 713 个）：

| 条目 | 第 1～5 名 | 第 16～20 名 | 最远 |
| --- | --- | --- | --- |
| 烹饪 | 香辛料、烤炉、热力学、热量、火 | 消化、食物、制造业、饥荒、食品保存 | 土星、国家、绵羊、民主 |
| 钓鱼 | 狩猎、玩耍、游泳、鱼、赌博 | 节日、玩具、指南针、函数 | 氮、银、硅、铜、碳 |
| 计算机科学 | 电子计算机、离散数学、语言学、逻辑、密码学 | 人工智能、算法、哲学、宏观经济学 | 木星、地球、土星 |
| 绘画 | 视觉艺术、书法、素描、电影、抽象艺术 | 现代主义、地图、文学、视频 | 木星、硅、氢、铁 |

去中心前，任意两个条目的相似度平均是 0.59、标准差只有 0.05，几乎分不开；去中心后标准差是 0.09。

备选的交叉验证办法：维基百科词条之间的链接关系，用 Milne-Witten 算法算两个词条有多相关。
