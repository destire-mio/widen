# 工业推荐系统是怎么防止“只推你看过的”的，以及怎么搬到记忆上

更新：2026-11-26

## 1. 工业推荐系统的一条流水线

抖音、YouTube 这类系统，推一条视频要经过 4 关：

| 关卡 | 做什么 | 防“只推老一套”的手段 |
| --- | --- | --- |
| 召回 | 从几亿条里粗选出几千条候选 | **多路召回**：一路按你的兴趣，一路按热门，一路专门做“探索”，各出一部分候选 |
| 排序 | 给每条候选打分：你会不会喜欢 | 分数只决定“合不合你”，不决定方向 |
| 重排 | 决定最终的顺序 | **打散**：同一类的内容不能挨在一起，比如同类之间至少隔 5 条（“硬打散”）；或者用 MMR、DPP 这类算法，在“合你”和“彼此不一样”之间找平衡（“软打散”） |
| 探索流量 | 专门留出一小部分位置给新兴趣 | 大约 **2% 的曝光**留给探索。短期内留存会略降，长期会恢复，最后反超对照组 |

来源：[Methodologies for Improving Modern Industrial Recommender Systems](https://arxiv.org/abs/2308.01204)（只读到摘要和检索结果片段，正文 PDF 没解出来）；[WeChat 图探索](https://arxiv.org/abs/2306.00009)；[华为个性化多样性重排](https://arxiv.org/abs/2004.06390)。

还有两个和我们直接相关的做法：

- **多兴趣**：一个人不是一个兴趣，而是好几个（MIND、ComiRec）。如果只用一个兴趣来代表这个人，最强的那个兴趣就会压住其他所有兴趣。另外，每个兴趣淡掉的速度不一样（MIP）。来源：[MIP](https://arxiv.org/abs/2207.06652)、[检索方法综述](https://arxiv.org/abs/2407.21022)。
- **曝光偏差**：一条内容被展示得越多，点击就越多，模型会误以为你更喜欢它。工业上的修正办法是按“被展示了多少次”反过来打折（逆倾向加权，IPS）。来源：[Bias and Debias in Recommender System](https://arxiv.org/abs/2010.03240)、[Popularity Bias 综述](https://arxiv.org/abs/2308.01118)。

## 2. Google 2024 的做法（我们最想搬的）

来源：[LLMs for User Interest Exploration in Large-scale Recommendation Systems](https://arxiv.org/abs/2405.16363)（RecSys 2024），以及续作 [User Feedback Alignment for LLM-powered Exploration](https://arxiv.org/abs/2504.05522)。平台是一个有几十亿用户的短视频平台。

1. **先建兴趣类别表，和具体用户无关。** 把所有视频按内容聚类，分 4 层，在第 2 层规划，这一层有 **761 个类别**，每个类别有一段文字描述。
2. **用户只用 2 个类别来代表。** 从他最近 30 天的历史里**随机抽 2 条**互动质量高的视频，看它们属于哪 2 个类别。这里是随机抽，不是取最常看的那 2 个。
3. **大模型预测一个“新”类别。** 给它这 2 个类别，让它说出下一个可能感兴趣的类别，要求和这 2 个都不一样。训练数据来自真实日志里“成功引入新兴趣”的例子，大约 25 万条。他们特意把数据做均衡：每个目标类别只留最常见的 10 种组合，一共 7610 条，免得模型总推那几个热门类别。
4. **离线算好，线上查表。** 761 × 761 = 57.9 万种组合，提前全部算完存成一张表，线上直接查。
5. **在新类别里找具体视频的，还是原来的推荐模型。** 大模型只负责定方向，具体挑哪条视频还是老模型来挑。
6. **续作：一个负责“新”，一个负责“对口”。** 负责新的模型用高随机性采样出 5 倍数量的候选，再由一个“对口”模型（拿用户的真实反馈训练出来的）挑出最好的几个。他们还发现：负责新的模型有 **40% 的概率重复**用户已有的类别；直接用强化学习去优化，模型会崩，开始“刷分”，只吐“猫、BTS、玩具”这种词。
7. **结果**：新兴趣的曝光更多，质量和只推老兴趣的方法相当，观看时长和活跃用户数都上涨了。论文正文里没有给具体数字。

## 3. 搬到记忆上：一一对应

| 推荐系统 | Widen |
| --- | --- |
| 一条视频 | 一个点子 |
| 兴趣类别 | 话题（方向） |
| 用户历史 | 用户记忆 |
| 只抽“互动质量高”的历史 | **只用关于这个人的记忆**：技能、资源、限制、讨厌的东西。AI 给过的建议、随口问过的问题不算。测试里 Mem0 存的东西有一半以上是这类 |
| 随机抽 2 个类别，不取最常看的 | **每次随机抽 2 条记忆当起点**，不取提到次数最多的。用来对抗测试里发现的“提得越多，越能把点子带跑” |
| 曝光偏差修正 | 一件事被提 4 次和提 1 次，当作同样重要。记忆按“说的是哪件事”合并，不按条数加权 |
| 多兴趣 | 把记忆分成几个独立的兴趣，不让最强的那个压住其他的 |
| 多路召回 | **三路出候选**：①近路：用他会的、有的东西；②探索路：从 2 条记忆出发，预测一个“挨着但没去过”的方向（Google 那一步）；③远路：完全不看记忆，从几个不同角度想 |
| 排序 | **评审**：看清理过的记忆，只判断“他做不做得了、愿不愿意做” |
| 重排打散 | 同一个方向最多只出 1 个点子；三路各占一定名额 |
| 探索流量 | **名额**：最终建议里至少一半来自探索路和远路 |
| 负责“新”的和负责“对口”的分开 | 想点子的不看记忆，挑点子的才看（D4） |
| 用户反馈训练“对口”模型 | 第一版没有反馈。第二版记下用户对每条建议的反应，用来调整 |

**和 Google 的区别：** Google 有几十亿条真实的“从 A 兴趣走到 B 兴趣”的记录，可以拿来训练。我们没有，只能先靠大模型自己的常识来判断“会 Go、手上有物流数据的人，下一步可能会对什么感兴趣”。这是第一版最大的不确定性，要靠 benchmark 来验证。

## 4. “猜你喜欢”是怎么挑探索内容的（2026-11-26 补充）

维护者指出：推荐系统不可能随便找几个话题来推。第一版插件里的“远方向”是随机抽的，相当于最粗糙的 ε-greedy，实测确实很牵强（例如“边听浪漫主义音乐边写感受”）。

工业上的做法分三层：

| 层 | 做法 | 例子 |
| --- | --- | --- |
| 候选从哪来 | **按人群行为找**：喜欢 A 的人还喜欢什么、看完 A 的人接着看了什么。不是按内容像不像来找 | 协同过滤；Pinterest Pixie 在“图钉-画板”图上做随机游走，**游走步数控制推荐的宽窄**，服务了平台 80% 以上的互动（[Pixie, WWW 2018](https://arxiv.org/abs/1711.07601)）；Google 2024 用的也是真实日志里“从兴趣 A、B 走到 C 并且看得开心”的转移 |
| 排序 | 预估“这个人会不会喜欢” | Google 续作里的“对口”模型 |
| 探索 | **有目标的探索**：在“预估还不错、但系统还不确定”的内容上加分（UCB），或者按“它是最佳选择的概率”来抽（Thompson 采样）。完全随机（ε-greedy）是最粗糙的做法 | Yahoo 新闻、DoorDash 菜系推荐、Facebook Reels 冷启动（[Eugene Yan 的总结](https://eugeneyan.com/writing/bandits/)、[Epinet](https://arxiv.org/abs/2412.04484)、[Google: Value of Exploration](https://arxiv.org/abs/2305.07764)） |

### 4.1 搬过来：用“维基百科读者的点击路径”代替“用户行为日志”

维基百科每个月都会公开一份点击流数据：读者从条目 A 点到条目 B 的次数，少于 10 次的不发布（[Wikipedia Clickstream](https://meta.wikimedia.org/wiki/Research:Wikipedia_clickstream)）。这就是“看完 A 的人接着看了 B”，是真实人群的转移数据，和 Google 用的日志是同一类东西。

| 推荐系统 | Widen |
| --- | --- |
| 用户行为日志里的“A → B” | 维基点击流里的“A → B”，只保留 6198 个基础条目之间的边 |
| Pixie：从用户的图钉出发做随机游走 | 从用户点亮的条目出发，在点击流图上做**带重启的随机游走**（个性化 PageRank） |
| 游走步数控制宽窄 | **重启概率就是取舍旋钮**：重启得多，就留在近处；重启得少，就走得远 |
| 对口模型给候选打分 | 模型打分：这个方向对这个人、这个问题有没有意思、做不做得了 |
| UCB：预估不错 + 不确定加分 | **总分 = 被走到的频率 × 对口分 + λ × 离亮区的距离**。λ 也是取舍旋钮 |

**取舍怎么定：** 不拍脑袋。benchmark 里扫几个 λ（比如 0、0.3、0.6），画出“合适率—好点子率”曲线，选达标线上的那个点。
